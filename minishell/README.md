# minishell

Bash의 핵심 동작을 C와 POSIX 시스템 호출로 구현한 42Seoul 2인 팀 프로젝트입니다. 명령 입력을 분석해 실행 가능한 구조로 변환하고, 파이프·리디렉션·환경 변수·시그널·빌트인 명령을 처리합니다.

## 프로젝트 정보

- 42Seoul 2인 팀 프로젝트
- 언어: C
- 주요 API: `fork`, `execve`, `pipe`, `dup2`, `wait`, `open`, `close`, `signal`
- 라이브러리: GNU Readline

## 팀 전체 구현 범위

- 명령어 파싱과 실행
- 파이프라인
- 입력·출력·추가 리디렉션
- 히어독
- 환경 변수와 종료 상태 확장
- `echo`, `cd`, `pwd`, `export`, `unset`, `env`, `exit`
- `SIGINT`, `SIGQUIT`, EOF 처리

## 개인 담당: 명령어 파싱

개인적으로 파싱 모듈을 중심으로 구현했습니다.

```text
사용자 입력
   ↓
파이프 구간 분리
   ↓
쿼트 상태를 고려한 토큰 분석
   ↓
환경 변수·종료 상태 확장
   ↓
리디렉션·히어독 분석
   ↓
실행 모듈에 명령 구조 전달
```

### 쿼트와 환경 변수

- 싱글 쿼트 내부는 리터럴로 처리
- 더블 쿼트 내부에서는 `$VAR`와 `$?` 확장
- 쿼트 밖의 환경 변수 확장
- 확장 결과에 따른 명령·파일명 처리

### 파이프와 리디렉션

- 쿼트 내부의 `|`, `<`, `>`는 일반 문자로 구분
- 파이프 단위로 명령과 인자 분리
- `<`, `>`, `>>`, `<<` 대상과 파일 디스크립터 정보 구성
- 확장 결과가 유효한 파일명 하나로 결정되지 않으면 `ambiguous redirect` 처리

### 히어독

- delimiter의 쿼트 제거
- delimiter가 쿼트되지 않은 경우 환경 변수 확장
- 히어독 전용 시그널 처리
- 입력 결과를 실행 단계의 표준 입력으로 연결

### 구문 오류

- 닫히지 않은 쿼트
- 파이프 앞뒤의 빈 명령
- 리디렉션 뒤에 대상이 없는 경우
- 예상하지 못한 연속 메타문자

## 실행 예시

```bash
make
./minishell
```

```bash
minishell$ export TARGET=STM32
minishell$ echo "$TARGET" | grep STM
STM32

minishell$ cat < input.txt | grep hello >> output.txt
```

## 핵심 기술 포인트

- 팀 전체 기능과 개인 담당 파싱 범위를 분리해 설명
- 단순 문자열 분리가 아니라 쿼트 상태에 따른 문맥 처리
- 환경 변수 확장과 리디렉션이 결합될 때 발생하는 예외 처리
- 파싱 결과를 실행 모듈이 사용할 구조로 변환한 과정

## 한계

- Bash 전체 문법을 구현한 셸이 아니라 과제 요구 범위의 핵심 기능을 구현했습니다.
- 와일드카드, 논리 연산자, 서브셸 등은 지원하지 않습니다.
- Makefile의 Readline 경로는 42Seoul macOS 클러스터 환경을 기준으로 설정돼 있습니다.
